## v1.10.40 改了什么（2026-11-01）

> 三件事，两件来自对 `deepseek-ai/dsh-superagent-prototype` 的借鉴，一件是消磨人的摩擦。

**① 授权强度（动工前的门）**
票面新增一行 `**授权强度**`：`explicit`／`inferred`／`none`
- `explicit` ＝ 主人明确要求（能引原话）
- `inferred` ＝ 职务自己推断的活儿 ⇒ **动工前必须补 `**授权**：主人已确认（时间）`**
- 没确认就动工 ⇒ `ticket-check --strict` 记一条真问题（`authorization-weak`）
- `ticket-relay.mjs` 建票按 `--origin` 自动写；**缺省 inferred**，绝不默认 explicit
- 存量已结票一律豁免，不追溯

**② 悬空票复验（续做前的复查）**
`[~]` 超 24h 或 `[v]` 超 12h ⇒ 再动之前补 `**复验**：YYYY-MM-DD HH:MM ✓ 请求人仍在／规则未变`
没补就继续动 ⇒ `--loop` 报「需复验」。一次复验管 24h，`[x]`／`[-]` 不要求。

**③ 行尾自动归一**
票板被写成 CRLF 时，`ticket-reply` 以前直接拒绝（每次都要人手工统一）。
现在写盘前自动归一并在输出打「行尾归一：CRLF N 处 → LF」；纯 LF 不变、不打这行。
想保持旧的拒绝行为加 `--strict-eol`。

> ⚠ 源头提醒：**PowerShell 的 `Add-Content`／`Set-Content` 在 Windows 默认写 CRLF**（实测 `61 0D 0A 62 0D 0A`）⇒ 写票板请用 node 的 `fs.appendFileSync(..., '\n')`。

## 二、装（五步）

1. 备份你现在的 `tools/` 与 `docs/`
2. `tools/` **整目录替换**（8 个脚本 ＋ `lib/` 2 个库）
3. `docs/` 只取模板与文档 —— **别覆盖你自己的票板／交接／角色分工** ✗
4. 配置 `docs/.ticketrc.json`（照 `.ticketrc.json.example` 改）：

```json
{
  "board": "docs/待办.md",
  "handoff": "docs/交接.md",
  "since": "2026-10-26",
  "debtSince": "2026-10-26T00:00",
  "lines": {
    "流程管理员": ["流程线", "流程", "F"],
    "调试工程师": ["调试", "调试线", "D"],
    "卡片工程师": ["卡片", "卡片线", "C"],
    "发布工程师": ["线上发布", "线上", "P"],
    "项目负责人": ["主人", "用户"]
  }
}
```

- `lines` **可选**：别的项目写自己的名字 ✓ 值是数组或字符串（按 ／ 、 , 拆）✓
- 别名里放一个 **1~2 位字母** ⇒ 它自动成为**票号字母** ✓（`["Q","开票"]` ⇒ `T-…-Q01`）
- 默认那五个职务始终保留 ✓ 混着写也认 ✓
- `debtSince` **可以写真实时刻** ✓ 写错会 **exit 2** ✗（不会静默按默认值跑 ✗）

5. 自检（**退出码 0、失败 0** 即通过 ✓ 用例数看输出末行 ✓ 别记数 ✗）

```bash
node tools/ticket-check-selftest.mjs
node tools/ticket-reply-selftest.mjs
```

## 三、验（退出码三档）

| 码 | 含义 |
|---|---|
| `0` | 跑完了 —— 普通报告下**不代表没有真问题** ✗（数在输出里）；`--strict` 下才等于「real 为 0」✓ |
| `1` | `--strict` **检出真问题** ✗；或 `ticket-reply` **拒绝写入** ✗ |
| `2` | **参数／配置／路径／可读性**非法 —— 一定伴随「什么都没做 ✓ 文件未改 ✓」|

```bash
node tools/ticket-check.mjs --json --strict   # 门禁一条命令：JSON ＋ 退出码
node tools/identity-check.mjs                 # 只验账不验票（四条恒等式 ✓ 与主检查器同口径 ✓）
```

## 五、口径（读数是三栏，不是一栏）

```
real = knownReal + unknown + unclassified
```
- `unknown` ＝ **无票号且判不了年代** ⇒ 仍算 `real` ✓ 但**不是「已确认的新增」** ✗
- 所以「还剩几件」的正确答法：**已确认 N 条；另有 M 条判不了年代** ✓ 单说 total 是错的 ✗
- 门禁要稳定 ⇒ `--assume-debt`（把 `unknown` 当历史债看 ⇒ 只改分组与门禁 ✓ **不改判定** ✗ JSON 里 `assumedDebt: true` ✓）

## 六、七条硬边界

1. **不回填历史票** ✗（补票号／补日期＝补造证据）
2. **别改 `tools/`** ✗ —— 要改就开票 ✓
3. **`--file` 只指活票板** ✗ —— 指归档文件取数**不可比** ✓（首屏会警告）
4. **回票只有首行用 `✅`** ✓ 正文用 `✓`／文字 ✓（`> ``` ` 引用围栏**不被扫描器排除** ✗）
5. **负责人／验收方／阻塞写职务**（或配置里的名字）✓ 代号与代指（我们／你们／对方）一律不合格 ✗
6. **`--max` 是本次总量上限** ✗ 不是「每批搬多少」；非法值 **exit 2 且不写盘** ✓
7. **临时项目只用 `mk-proj.mjs` 造** ✗ 不手写路径；`exit=$?` 必须**紧挨**被检命令 ✓（命令块别以 `rm` 结尾 ✗）

## 七、回滚

包内**不含任何状态** ✓ 回滚＝把你自己的备份解包覆盖 ✓ 工具不会动你的票板／交接 ✓

## 八、报问题给四样

1. 完整命令（含所有参数）
2. 完整输出（**stderr 也要** ✓ 有些提示在 stderr ✗）
3. 取数行：`取数：时刻｜行数｜sha256 …`（对账用 `contentSha256` ✓ 别用短 hash ✗）
4. 期望 vs 实际（尤其退出码 ✓）

## 九、装完先观察三件

1. 新票是否写全 **票号／职务负责人／验收方式**
2. 回票是否**只有首行用 ✅**，接收方能否照证据复验
3. 真实归位前，**预演给人的归属判断**与实际是否一致
