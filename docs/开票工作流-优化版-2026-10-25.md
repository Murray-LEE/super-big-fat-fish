## 0. 五条铁律

1. **状态是字段，不是形容词** ✓ —— 票头第一段就是状态位，绝不许从正文关键词猜 ✗
2. **票 = 细节，交接 = 指针** ✓ —— 两处都写人话，措辞漂移是必然的 ✗
3. **验收方式本身也要被验收** ✓ —— 不许自指、判据要能区分真假、要标在哪台机器什么权限 ✓
4. **符号不等于证据** ✓ —— 有 `✅` / 有票号 / 有标签，只证明"记录了"，**不证明"做对了"** ✗（模板示例、代码块、正文说明都不算实际记录 ✗）
5. **谁验收谁的队列要说清** ✓ —— 开工只看"我要处理的"会漏掉"我要验收的 `[v]`" ✗

### 0.1 备份失败怎么办（v1.2 起 · v1.3 收紧一次）

| 类型 | 例子 | 备份失败时 |
|---|---|---|
| **不可逆 / 批量** | 数据迁移、批量改卡、整库覆盖 | **停** ✗ 记录失败原因 |
| **有独立恢复路径**（v1.3：**别只看按钮名** ✗） | 「🔄 重新开始」（旧剧情先存进存档 ✓ 有独立恢复路径 ✓） | 可继续 ✓ 但必须在闪行与交接写明"备份失败" ✗ |
| **没有独立恢复路径** | 「🗑 清空」、覆盖式写入 | 按不可逆处理 ✓ 备份失败就停 ✗ |

> 判据是"**这次操作失败后还能不能回到原状态**"✓ 不是"这个按钮听起来危险不危险"✗。

## 1. 三份文件

```
docs/
├─ 角色分工.md    ← 契约：谁改什么、不许动什么、验收授权、收工标准（很少改）
├─ 待办.md        ← 票：状态与验收细节（只追加，票永不删）
└─ 交接.md        ← 顶部：当前状态速查（可更新）｜底部：历史流水（只追加，只写指针）
```

一项工作的状态**只在一个地方**维护 → **票里** ✓ 交接摘要若转述状态，必须带票号与时间 ✓ 两者不一致时，以票为准 ✗ 不是以"哪个文件最后保存"为准 ✗。

## 2. 角色与所有权

| 角色 | 负责 | 可以改 | 绝对不许改 |
|---|---|---|---|
| **代码线**（调试/系统） | 引擎、代码、服务端、工具、部署、排障 | 代码目录、构建脚本、工具 | 内容数据、别人负责的配置 |
| **内容线**（卡/文案/人格） | 内容、文案、数据 | 内容数据文件、自己新建的工具 | 代码目录、既有测试脚本 |
| **发布线**（分发/平台） | 平台配置、上架、费率、账号 | 平台侧配置、发布脚本 | 本地代码与内容 |
| **人类（主人）** | 拍板、给真实素材、裁决体验 | 什么都可以，但不写实现细节 | —— |

要点：

- **数据与代码分离** ✓ 内容线只碰数据，代码线只碰代码 ✓
- 按**文件所有权**划分 ✓ 但要在契约里写清：**同一文件的实际写入仍需协调** ✓（按字段分工 ≠ 文件级隔离 ✗）
- 允许"**临时接管**"：接管前确认原线已停止写、重读最新版、记录接管边界 ✓ **超时不构成自动接管** ✗

## 2.6 跨会话派活插件：**它只是邮差**（2026-10-28 · 待装）

> 候选：`dsh-cross-session-approval@0.3.10`（10 个工具：spawn／send／reply／status／read／list／broadcast／rename／archive／approve）
> 它正好补我们唯一没被工具解决的环节 —— **主人当总线** ✗（`ticket-relay` 只把传话格式化成票 ✓ 仍要人去说 ✗）

**四条规矩（装之前就生效 ✗ 不是装完再补 ✓）**：

1. **票板是唯一台账** ✓ 插件登记表（`<工作区>/.cross-session/registry.json`）**不是账** ✗
   - 它只有 **200 条上限 ＋ LRU 淘汰** ✗ 且**不建议进 git** ✗
   - ⇒ **永远不许**拿 registry 当"这活办完没"的依据 ✗ 依据只有票板 ✓
2. **task 里必须带票号** ✓（`T-20261028-D01`）⇒ 对方回信时能对上票 ✓ 否则又是一条孤立消息 ✗
3. **回票顺序固定**：**先写票板**（`> ✅ …回「…」（T-…）`）**再** `cross_session_reply` ✓
   - 反过来 ⇒ 消息到了、票板没记 ⇒ 下一次对账就少一条 ✗
4. **它的限制照抄不扩写** ✓：`approve` 只有**请求会话的创建者**能批 ✗（不能替代"验收方签收"✓）／投递成功 ≠ 任务完成 ✗／跨工作区寻址受限 ✓

**沙箱里"新建文件"会被拒，但改写已有文件可以**（v1.10.34 · 2026-10-28 02:3x 现场）

> 症状：cs-team 里跑 `ticket-reply --write --close` ⇒ `EPERM: copyFile '待办.md' -> '<项目目录>\.backups\…'`
> 但**同一个文件**（`docs/待办.md`）的改写成功 ✓

**排查结论（两层都排除过）**：
1. **不是 ACL** ✗ —— `.backups` 与 `docs` 的权限项**一模一样**（Authenticated Users: Modify ✓）；用 ACL 诊断脚本跑过 ⇒ `NOT_THIS_CLASS` ✓ 无需修权限 ✓
2. 差别在**在该目录里新建文件**被沙箱拒 ✓ 改写已有文件可以 ✓

**处置（工具层）**：`writeBackup()` ⇒ 先试 `<root>/.backups` ✓ 写不进去就退 `<系统临时>/fj-backups` ✓ **并把实际路径打出来** ✗ 不静默 ✓
　⇒ 备份是安全措施 ✗ 不许因为它写不进去就让整次写入失败 ✓（但必须让人看见退到哪 ✓）
　⇒ 用例 **73**（不可写 ⇒ fallback）／**74**（可写 ⇒ 仍用仓内 ✓ 不许一律退临时 ✗）

**票板写入权：同一时刻只有一个写的人**（2026-10-28 起）

| 角色 | 在哪 | 能做什么 |
|---|---|---|
| 流程管理员（派活那个会话）| **cs-team** | **写票板**（开票／回票／关票／验收）、派活、催办 ✓ |
| 桌面这条会话（工具/规范）| desktop | 改工具与规范 ＋ **只读**票板 ＋ 打包 ＋ 对外回执 ✗ **不写票板** ✗ |
| 三条线（调试／卡片／发布）| cs-team 待命 | 只在自己的票块内追加回票 ✓ 改代码 ✓ |

**为什么**：票板是一个文件 ✗ 两边同时写 ⇒ 后写的覆盖前写的 ✓（我的 `--write` 都是整文件重写 ✗）
⇒ 约定：**票板写入权默认在 cs-team** ✓ 桌面这边要写（公告／规范条目除外）必须先声明 ✓

**观察三条（装后两周）**：主人转达次数 ↓ ／ 回票延迟 ↓ ／ **票板与 registry 有没有说法不一致** ✗（有 ⇒ 立刻停用插件 ✗）

**作用范围：能不能只在这个工作组里生效？**（2026-10-28 · 主人问）

| 层 | 事实 | 结论 |
|---|---|---|
| **工具可见性** | DSH 插件按 **profile**（`~/.dsh/profiles/<名>/package.json` 的 `dsh.profile.bundles`）加载 ✗ | 装进现在的 `desktop` ⇒ **该 profile 的每个会话都有这 10 个工具** ✗ 不按工作区隔离 ✗ |
| **数据** | 登记表落在 `<工作区>/.cross-session/registry.json` ✓ `cross_session_list` 默认只列**当前工作区** ✓ | 数据天然按工作区 ✓ |
| **外溢入口** | `all_workspaces: true` 能看别的工作区 ✗ ／ `cwd` 能指定别的目录 ✗（最高档才算） | **只能靠自律 ✗** ⇒ 规矩：**不传 `all_workspaces`、不传 `cwd`** ✓ |

**两种真正隔离的办法**：

1. **独立 profile（推荐）** ✓ 新建如 `~/.dsh/profiles/workteam`，只在那里加这个 bundle ⇒ **只有那个 profile 的会话有工具** ✓ 其他 profile 一点不受影响 ✓
   代价：另开一套 profile 的插件配置 ✗（工作区／项目文件是共享的 ✓ 无碍）
2. **专用 agent preset** ✓ 同一个 profile 里写一个 preset，只在 preset 里挂这 10 个工具 ⇒ 用该 preset 的会话才有 ✓
   代价：要写 Cordis 组合 ✗ 改错会影响 preset 使用者 ✓ 更细但更容易互相牵连 ✗

> 不推荐"装到全局、靠规则约束用法"✗ —— 工具一旦可见，别的会话迟早会误用 ✓

## 2.5 传话不是通道（2026-10-27 · 主人反馈"传话后就不互相开票了"）

> **主人传话 ≠ 已经通知到位** ✗ 它只是一次**口头提醒** ✓ 提醒会丢 ✓ 票不会 ✗

| 传话内容 | 该做什么 |
|---|---|
| 有**动作**（要谁去改／去查／去跑）| **开票** ✓ 一条命令：`node tools/ticket-relay.mjs --from 我 --to 对方 --title "…" --write` |
| 有**结论**（谁做完了、验收结果）| **回票** ✓ 落到那张票里 ✗ 只在对话里说＝没留痕 ✗ |
| **纯信息**（不要求任何人做事）| **不开票** ✓ 但回一句「只通知 ✓」✓ |

**为什么必须写死**：让"传话"和"开票"变成**同一个动作** ✓ 否则人一定选省力的那个 ✗（写八行票 vs 说一句话 ✗ 结果一定是传话 ✗）
⇒ `ticket-relay.mjs` 就是为此存在的：**一句话开出一张合规票** ✓

**它顺带解决三件事**：票号自动递增（不撞号 ✓）／负责人·验收方**只能写人名**（写代号直接报错 ✗）／写完**先自检**，这张票若会自带问题（例如缺验收方式）⇒ **拒写** ✗

## 3. 票：格式与硬规则

### 3.1 票头（状态位必须在最前）

```markdown
## [ ] [卡片→调试] 标题（2026-10-25 10:40 UTC+8）
## [~] [卡片→调试] 标题        ← 处理中（票内加一行「认领：<线>（10:40）」✓ 认领是**事件** ✓ 状态符才是当前状态 ✓ 换人要追加一行、不覆盖旧认领 ✗）
## [v] [卡片→调试] 标题        ← 回票了，等对方复验
## [x] [卡片→调试] 标题        ← 已验收通过
## [-] [卡片→调试] 标题        ← 已取消（必须写理由）
```

| 规则 | 为什么 |
|---|---|
| 状态符只有 ` ` `~` `v` `x` `-` 五种，**在第一段方括号里** | 写成 `## [宿主→系统线] 标题` 会让 `grep '^## \[ \]'` **永远是 0** ✗ 不是"没票" ✗ 是"永远扫不到" ✗ |
| 方括号里**只放状态**，路由放第二个方括号 | 一个方括号装两样东西，机械判据就没法剥 ✗ |
| **绝不许从正文关键词猜状态** | 票正文里只要出现"结票改 `## [x]`"，判据就**自指** ✗ 未结票被判成已完成 ✗ |
| 时间带**时区**；同一天多次改动带**时分** | 容器日志 UTC ✗ 服务日志 UTC+8 ✗ 同一件事差 8 小时 ⇒ 时间线判反 ✗ |
| **负责人／验收方写具体责任人** ✗ 不写代号 ✓ | 写 `D`／`C`／`F` ⇒ 接手的人要先去查代号表，等于**把信息藏起来** ✗ 写「调试」「卡片」「流程线」或人名 ✓ |

### 3.2 票号

`T-<YYYYMMDD>-<线代号><两位序号>`，例 `T-20261025-D03`

- 线代号固定：`D` 调试 / `C` 卡片 / `P` 线上（各项目自定 ✓）
- **序号按线各自递增** ✓ 不要所有线抢"最大号 +1" ✗
- 用途：回票靠**票号**定位 ✓ 交接只写票号 ✓ 不再复述整张票 ✓

**位置规范（v1.2 新增 · 现场踩过）**：

- 票号写在正文 `**票号**：T-…` 一行，**紧贴票头第二行**（推荐 ✓ 位置可预期 ✓）
- 但**别让检查器依赖这个位置** ✗ —— 现场在票头与票号之间插了「认领」行和空行 ✗ 票号被挤到第 4 行 ✗ 原检查器只看后 2 行 ⇒ **样本漏一张**（3 张而不是 4 张 ✗）
- ⇒ 约定：**规范紧贴第二行 ✓ 检查器按票块读** ✓（v1.4 更正 ✗）

**检查器到底怎么读（v1.4 对齐实现 · 原文写错了）**：

| 原文（v1.2 口径）✗ | 实现（v1.3 起）✓ |
|---|---|
| "检查器扫**前 10 行**" | **先切票块**（票头 → 下一票头之前）✓ 票号在**本块内任意位置**都能读到 ✓ |
| "10 行"是个**固定窗口** ⇒ 认领行 ＋ 复现步骤一多，票号照样被挤出窗口 ✗ | 块内读 ⇒ **没有窗口** ✗ 夹多少行都不漏 ✓ **但绝不跨到下一张票** ✗ |
| 窗口跨票 ⇒ 甲票缺号会扫到乙票的号 ⇒ 误报"票号重复"✗（GPT 反例 3.1 ✓） | 本块读 ⇒ 甲票**如实报缺票号** ✓ 乙票**不背**甲的错 ✓ |
| —— | 同一块内**声明行**（`**票号**：T-…`）出现**两个不同**票号 → 报「票号歧义」✓ 一个都没有 → 报「缺票号」✓ **不从正文/下一票补猜** ✗ |

> **v1.6 补一句把口径钉死**：**歧义只看声明行** ✗
> 正文里提到别人的票号是**常态**（"我开的第一张就是 `T-…-D05`"、"见 `T-…-D01` 的回票" ✗ 按"出现过就算"实现会把三张票判成歧义 ✗）
> ⇒ 声明行才是"这张票是谁"，正文里的号只是**指路** ✓ 只计数、不判定 ✓ **口径与 §9 的"示例不参与判定"是同一条** ✓

> **顺带一条（2026-10-25 夜 · 人也会踩同一个坑）** ✗：我为了看"文件尾部"用了 `sed -n '73,89p'`，可那个文件 **91 行** ⇒ 正好把第 90-91 行截掉 ✗（就是那句 `process.exit` ✗）
> ⇒ **固定窗口读文件，尾部一定看不见** ✓ 这正是本节批判的"前 10 行窗口"的同族错误 ✗ 只是从"检查器"换成了"人" ✓
> ⇒ 看尾巴用 `tail` ✓ 看长度先 `wc -l` ✓ 别用行号猜文件有多长 ✗

> 一句话：**位置靠约定（紧贴第二行）✓ 判据靠结构（本块内）✓ 两者都不许互相依赖** ✗

负责人：调试｜验收方：卡片｜阻塞：无   ← v1.3：只留**当前**状态在票头 ✓ 删掉重复的 `**状态**：` 行 ✗

```

按需追加：环境、复现步骤、证据、依赖、数据操作风险、回滚点。
**纯说明性修订**不强制填运行环境、基准测量、多套回滚 ✗。

### 3.4 验收方式：**可自证**是第一要求

四种都算数 ✓ —— 关键不是"必须是命令" ✗ 而是"**对方能自己核对**" ✓：

| 形式 | 例子 | 适合 |
|---|---|---|
| 命令 | `node tools\run-all-tests.mjs` → 16 组全绿 | 有 shell 的线 |
| 读字段 | 读 `data/x.json` 的 `provider.model` = `deepseek-flash` | 没 shell 的线 ✓ |
| 截图 | 800×1280 与 1500×900 各一张 + 应看到什么 | 布局/界面 ✓ |
| 样本对照 | 改前 3 段 vs 改后 3 段 + 明确检查项 | 文风/文案 ✓ |

**四条硬约束**：

1. ✗ **不许自指** —— 想证明"文件里没有密码"，写 `grep -c '<密码>' 待办.md` 会把密码写进被检文件 ⇒ 永远命中 1 ✗
   → 换判据（v1.3 收窄 ✗）：**哈希只证明"和某个已知版本一致"** ✗ 行号会随编辑漂移 ✗ ⇒ 正解是**先划清被检数据范围** ✓ 用**已知阳性/阴性样本**验证判据有区分能力 ✓ 正则断开匹配串 ✓ 换独立观察点 ✓
2. ✗ **判据要能区分真假** —— 没测基线就写"期望 0"是猜 ✗ → 先跑一次看现状 ✓ 或明写"改前未采集" ✓
   **现场反例（2026-10-25 夜 · 我自己犯的 · 已开票又被自己撤销）** ✗：
   我拿**一次恰好通过**的运行（端口空闲 ⇒ 那一组是绿的）去"测失败路径"，得到 `exit=0`，就断定"有组失败也不返回非零" ✗ 报了票 ✗
   调试回票说"这行本来就在"，我一验：`process.exit(bad.length ? 1 : 0)` 在 **baseline 第 91 行**就有 ✓ 占住端口让组必红后 `exit=1` ✓
   ⇒ **测失败路径之前，先证明"这次真的失败了"** ✓ 否则你测的是"成功时的退出码"✓ 然后得出一个假结论 ✗
3. ✓ **标执行位置与权限**
   ```bash
   # @容器内 · 普通用户
   grep -c '…' /workspace/proj/docs/待办.md
   # @宿主机 · sudo
   sudo -n docker exec <容器> sh -c '…'
   # @无 shell 的线 → 由宿主线代跑（注明代跑者）
   ```

   **并且要说清"这是谁的环境"（v1.2 新增 · 现场自我更正）**：
   现场曾写「人设线没有 shell，跑不了检查器」✗ —— 那是**那一个会话的沙箱策略** ✗ 不是"线的属性" ✗
   实测人设线能正常跑检查器 ✓ 她还反过来提醒：**把会话级策略写成线的属性，下一个会话换回受限策略就失效** ✗，而且会让别人**干脆不去试** ✗

   ⇒ 描述环境时限定作用域，三种选一：
   - `该会话当前`（本次沙箱/权限就是这样 ✓）
   - `该线约定`（这条线长期这么干 ✓）
   - `该机器`（物理/容器层面的事实 ✓ 如 Windows 有 ACL、容器内无 sudo ✓）
4. ✓ **注意退出码** —— `set -e` 下 `grep -c` 命中 0 是**退出 1** ✗ 用 `|| true` 或 `if ! grep -q` ✓
5. ✗ **别把会增长的绝对数字写进判据**（v1.8）—— 写**关系**：`悬空 = 0`／`全部能落到票`／`14/14 通过` ✓
   反例（现场）：票里写"期望 **8 个**交接指针" ✗ 另一条线实测 10 个就质疑 ✗ —— 那个数会随历史自然长 ✓
   ⇒ 下一个人跑出来对不上，就开始怀疑自己 ✗ 然后**开始忽略这条判据** ✗（比写错更贵 ✗）
   ⇒ 必须写数字时**附取数时刻**：`10 个（2026-10-26 00:30 取）` ✓

### 3.5 凭据禁区

**票面 / 交接 / 验收命令里出现凭据 = 把凭据写进历史** ✗

- 票与日志是**永久留存物** ✓ 事后只能轮换，而**旧值仍躺在历史记录里** ✗

**别的项目用别的线名？写进配置就行** ✓（v1.10.26 · Q线反馈）

## 4. 回票：不点名就等于没回

### 4.1 模板

```markdown
> ✅ **【2026-10-25 10:52 UTC+8 · 调试：<结论一句>】回「<原票标题关键词>」（T-20261025-C03）**
> 状态：**[v] 待验收**
>
> **改了什么**：1. … 2. …
> **实测（改前 → 改后）**（证据标签：自动测试实测 / 目标环境实测 …）
> | 指标 | 改前 | 改后 |
> |---|---|---|
> **请复跑**：`<方式>`（@位置 · 权限）  期望：<具体预期>
> **已知限制**：<没解决的，别藏>（无则写"无"）
```

> ⚠ **回票只有首行用 `✅`** ✓ 正文表示通过请用 `✓` 或文字 ✓ 演示边界符请用代码围栏 ✓
> 　—— 正文多写一个 `✅` 会被切成**新记录** ✗ 影响记录统计与定位诊断 ✓ 特定文本下**会影响归位** ✗
> 　**v1.10.32 起**：`> ``` ` **引用围栏也认** ✓ 块里的 `✅` 不再被当成回票（以前会假红 ✓ 见 T-20261027-P02）

### 4.2 为什么必须点名

只追加 + 多线交叉 ⇒ **"回票在原票下面"是错的** ✗
实测：A 线开票在第 223 行，回票落到了第 246 行另一张票之后 ✗ 扫描器按相邻段落判断，判成未处理，差点去催一件做完的事 ✗。

### 4.3 回票 ≠ 完成

- 回票只把状态推到 **`[v]` 待验收** ✓
- 只有**票面约定的验收方**给出结论，才改 `[x]` ✓
- 提交修复的人**不因提交自动成为验收人** ✗
- 低风险任务（错字、无共享影响的小修）可在契约里**预先授权按约定自验收** ✓ 并写明"按约定自验收" ✓

### 4.4 改前基线缺失怎么办

写 **"改前未采集"** ✓ 不补造数字 ✗
不写"自然度提高 35%"这种**没有定义的分** ✗。
性能类要给场景、样本数、环境是否可比 ✓ 单次数字不能写成"稳定提升" ✗。

### 4.6c 回票里提到**别张票**的票号，必须包行内代码（v1.10.15 · 四线实测撞出来的）

现场：在 C03 的验收回票里**裸写**了另一张票的号（`T-20261026-K03`）✗
⇒ 工具判「一段回票里出现多个票号 ⇒ 不猜 ✗」⇒ 这条回票**归属不明** ✗ 还污染**所有人的归位预演** ✗

**写法**：

- 引用别张票 ⇒ 写成 `` `T-20261026-K03` `` ✓（行内代码**不参与**票号判定 ✓）
- 自己的票号正常写 ✓（那是归属依据）
- 只写"K03 那张票"这种**不带 T- 前缀**的说法也安全 ✓

> 工具没错 ✓ 它不猜是对的 ✗ 错在写法 ✓ —— 这与我在文档里写"回票要写清楚"是两回事：
> **"写清楚"不等于"可以裸写号"** ✗

### 4.6b 改标题 = 让旧回票失联（v1.10.11 · 五线现场）

回票靠 `回「标题」` 或票号定位 ✓ 而票号是后加的 ✗ 很多老回票只有标题 ✓
⇒ **改票头标题**，那些 `回「旧标题」` 会立刻变成"对不上任何票的标题"✗
⇒ 现场看见的报错长得像"回票写错了"✗ 其实**是被点的那张票改了名字** ✗

**写法（不是判据 ✓）**：

- 结票、改结论、补说明 ⇒ **写在正文** ✓ 别改票头标题 ✗
- 要留痕 ⇒ 在标题**末尾追加**〔…〕✓ 别替换原句 ✓（`标题〔标题已证伪：实际在镜像层〕` ✓）
- 工具现在会把"写了一个标题但对不上任何票"单独归一类 ✓ 并提示"可能标题被改过 ✗ 或票已归档 ✗"

### 4.6 批量结票怎么写（v1.10.2 · 第一轮实测问出来的 ✓ 写法建议，不是新判据 ✗）

现场（线上发布线，2026-10-26）：34 条"定位不了"里 **29 条**是同一个写法问题 ✗

| 写法 | 工具的处境 | 结果 |
|---|---|---|
| `> ✅ **【… · 卡片线：验完 → 结票 [x]】**` | 没有「回『标题』」、没有票号 ⇒ **认不出属于哪张票** ✗ | 只能列进"定位不了" ✓ 不是 bug ✗ |
| `> ✅ **【… · 6 张全部复验通过，已全部结 [x]】**` | 一条回票结 **6 张** ⇒ 按号归位**数学上无解** ✗ | 工具拒绝 ✓ 这是对的 ✓ |
| `> ✅ **回「某票」（T-…）**` ＋ 后面写结论 | 有号或有标题 ⇒ 能定位 ✓ | 正常 ✓ |

**建议（写给想让自己回票可归位的人）**：

1. **一张票一条回票** ✓ 批量就写多行，每行一个 `回「标题」（T-…）` ✓
2. 用"结票"当动词没问题 ✓ 但**别用它替代**「回『标题』」✗
3. 票号必须与**声明行**一致 ✓ 引用一个**没有声明**的号 ⇒ 工具会报"没有这张票的声明"✓ 先查是号写错，还是那张票根本没开 ✗

> 这条**没有**给检查器加任何判据 ✗ —— 它只是在解释：**工具认不出"这是哪张票"，不是它坏了** ✓
> 剩下的 5 条（4 条引用未声明号 ＋ 1 条一条多号）同理 ✓

### 4.5 回票归位：一对判据 ＋ 三步搬运（v1.6 · 五线现场）

回票落错位置有**两个方向** ⇒ **必须成对实现** ✗ 只做一个，人会只修一半 ✗

| | 长什么样 | 检查器报什么 |
|---|---|---|
| **A** | 本块**有** `✅`，但点的是**别的票** ⇒ 别人的回票被塞进了这块 | 「回票指向别的票」|
| **B** | 本块**没有** `✅`，但文件**后面**出现了它的票号/标题 ⇒ 它自己的回票被塞到了别处 | 「回票不在票块内」|

**归位三步**（谁都能执行 ✓ 别手工缝 ✗）：

1. **先备份**票板 —— 放**仓库内** `.backups/` ✓ 别放 `/tmp` ✗（见 §11.2）
2. **按声明票号定位**目标块 ✗ 别用"块内出现过这个号"✗
   匹配顺序（**声明优先** ✓ 这是通则，不只票号）：
   ① 独占一行的 `**票号**：<id>` ✓ ② 票头行含号 ③ 块内出现过号 —— **最弱，必然误伤** ✗ 只能当兜底 ＋ 人工确认
   实测代价：用第 ③ 种匹配，把 C01 的回票插进了 D05 的块 ✗（因为 D05 正文里写着"我开的第一张就是 C01"✗）
3. **整段搬**（`> ✅` 那一整组引用行）✓ 内容一个字不改 ✗ 搬完**两向都复跑**（A 与 B 都该消失）✓

> **五线以上的真发现**（K 线登记当天就抓到一条）：最需要被检验的**不是"谁在干活"** ✗
> 而是"**谁的证据落在了正确的位置**" ✓ 四线还能靠人肉对一下 ✗ 五线之后位置错了没人会发现 ✓ 只有 lint 会发现 ✓

> ⚠ **搬之前先看这条**：只有回票首行用 `✅` ✓ 正文用 `✓`／文字 ✓ 否则你可能搬的不是你以为的那条 ✗

**工具（v1.7）**：`tools\ticket-reply.mjs` —— 只做"搬"，不做判断谁对 ✗

```bash
node tools\ticket-reply.mjs                         # 预演：会搬哪几行、搬去哪张票（**不写盘** ✗）
node tools\ticket-reply.mjs --write                 # 落盘：先快照 → 逐条搬 → 内容守恒校验 → 复跑 lint
node tools\ticket-reply.mjs --write --close T-…-H02 # 搬完再把该票 [v] → [x]
```

- **默认不写盘** ✓ —— 它改的是共享文件 ✗ 共享文件的每次改写都该先被人看一眼 ✓
- 定位**声明优先** ✓ 猜不准就**不动**并报出来 ✗（宁可留给人，也不制造一个"看起来归位了"的假象 ✗）
- `--close` 的三道闸：只有 `[v]` 能推 ✓ 块里**必须已有回票记录** ✗ 否则拒绝 ✓ 只改票头那一行 ✓ 多改一行就中止 ✗
- 搬错了：把 `.backups\<名字>-<本地时间>.md` 整份复制回去 ✓ 别手工缝 ✗
- ⚠ 它只保证**结构**（位置对）✓ 不保证回票内容可信 ✗ 验收仍走票面约定的验收方 ✓

## 7. 一轮完整流程

1. **读上下文**：契约摘要 → 当前速查 → **两个队列**（v1.3 修 ✗）：
   · **我要处理的** `[ ]` / `[~]` ✓
   · **我要验收的 `[v]`** ✓ ← 原来写"已 `[v]`/`[x]` 跳过"✗ 会让"回票了但没人验"从双方视野消失 ✗
   别只按状态跳过 ✓ 要按"**现在轮到谁响应**"✓ 不要求读完全部流水 ✓
2. **整理成票**：现象 → 票；低风险同线小改按简化规则 ✓
3. **认领**：`[ ]` → `[~]` ＋ 一行「认领：<线>（时分）」✓
4. **复现/取证**：能复现就复现 ✓ 不能则做只读调查并标"未复现" ✓
5. **留恢复点**：按改动性质备份 ✓ 校验备份能读回 ✓
6. **实施**：只改自己的地盘 ✓ 保护别人未提交的改动 ✓
7. **回票**：改了什么 + 改前→改后 + 已知限制 + 复跑方式 ✓ → `[v]`
8. **验收**：按票面标准判 通过/失败/阻塞 ✓ 通过才 `[x]` ✓

1. **状态是结构化字段** ✓ 不是正文关键词 ✗（否则自指 ✗）

### 9.0 自测必须有一块**脏板**（v1.10.15 · 四线实测）

跑完要能对上：`total = real + debt` ✓ `real = knownReal + unknown + unclassified` ✓ `sum(byKindReal) = real` ✓ `sum(byKindDebt) = debt` ✓

> **`identity-check` 的边界（五线线上线 06:1x 实测指出 ✓ 我采纳）**：
> 四条式子是**同一份 lint 输出**算出来的 ⇒ **结构上恒成立** ✗ 它**做不出"炸"** ✗
> 　**能抓**：① 别人脚本里写错的式子 ✓ ② **字段接线错误**（比如 `unclassified` 没进 `real` ✗ —— 那正是 v1.10.2 修过的 bug ✓）

### 9.2h 授权强度：谁的话算数（v1.10.39 · 借 dsh-superagent 的授权模型）

> 参照：`dsh-superagent-prototype` 把授权分三级 —— **explicit（本人提出）／inferred（推断）／not admitted**
> 并且写死一句：**消息、评论、被引用的文档都是"决策的输入"，不能改变权限** ✓ 我们借这一条 ✓

| 强度 | 在我们这里的表现 | 算不算闭环 |
|---|---|---|
| **explicit** | 票面写的**负责人**或**验收方**本人回票 ✓ | 算 ✓ |
| **inferred** | **别人替他们回**（署名是第三个职务）⇒ 标「**代回**」✗ | **不算** ✗ 需本人确认 ✓ |
| **not admitted** | 口头传话／群里的"他说行"／转述 ✗ | 不算 ✗ 必须落到票上 ✓ |

**例外（放行）**：**项目负责人（主人）**的署名一律放行 ✓ —— 他是授权源头 ✓

**判法**（`impersonatedOf`）：从回票**首行** `【时:分 · 职务】` 取署名 ⇒ 归一成标准职务 ✓
　认不出（自由文本如「主人确认 + 结清」）⇒ **不猜** ✗ 不判代回 ✓
　**只管活跃票 ＋ 2026-10-30 之后开的票** ✓ 老票不回填 ✗
　结果进 `--loop` ③（凡事有交代）：代回会列出来，并写清"谁签的、该谁签" ✓

**另一条借来的原则**：**A healthy state takes no space** ✓ ⇒ `--loop` 健康时**只打一行** ✗
　全绿：`✅ 六问全闭环 ＋ 无代回`（不再逐段写"（空 ✓）"✗）｜要逐段看全貌 ⇒ `--loop --verbose` ✓

#### 9.2h.1 票面的**授权强度**：动工前的门（T-20261101-F02 · 2026-11-01）

> 上面那套（代回）是**事后**标"签名的人不对" —— 活儿已经干完了 ✗
> 这一节是**事前**：**没授权的活儿不进活跃队列** ✓

票面新增一行（放 `**负责人**` 之后 ✓）：

```
**授权强度**：explicit｜inferred｜none
```

| 档 | 含义 | 能不能动工 |
|---|---|---|
| **explicit** | 项目负责人本人明确要求（**能引原话** ✓）| 直接动 ✓ |
| **inferred** | 职务自己推断出来的活儿（自查发现／跨线顺手／笔记里发现的问题）| **动工前必须有主人确认** ✗ 票面补一行 `**授权**：主人已确认（YYYY-MM-DD HH:MM）` 才许执行 ✓ |
| **none** | 没人要的活儿 | **不许进活跃队列** ✗ 要么补授权、要么作废 `[-]` ✓ |

**怎么生成**：`ticket-relay.mjs --origin …`
　`--origin 主人原话` ⇒ `explicit` ✓｜`--origin 自查`／`推断` ⇒ `inferred` ✓｜`--origin 无` ⇒ `none` ✓
　**缺省必须是 `inferred`** ✗ 绝不默认 explicit ✗（"默认有授权"是最坏的默认 ✗）

**怎么判**：`--strict` 里归 `授权强度不足`（code `authorization-weak`）
　· `inferred` ＋ 还在 `[ ]`／`[~]` ＋ 块里没有 `主人已确认` ⇒ **一条真问题** ✗
　· `none` ＋ 还在活跃队列 ⇒ **一条真问题** ✗
　· **存量票一律豁免** ✗：没有 `**授权强度**` 这一行的老票**不追溯** ✓（否则 73 张存量票会集体变红 ✗）

### 9.2f 版本节奏：**小修不打包、不要回票**（v1.10.33 · 主人："版本升得太频繁"）

> 主人原话：**"你版本升得太频繁，可以热修的小修复不需要回票，只有中大修复需要回票"** ✓

**三档（判法由 `node tools/release-size.mjs` 给 ✓ 只读）**：

| 档 | 判据（对着上一个发行包比） | 处置 |
|---|---|---|
| **热修** | 只改 ≤1 个工具文件 ／ ≤15 行 ／ 不是新增文件 | **原地改** ✓ **不打包** ✗ **不升版** ✗ **不要回票** ✗（记交接 ✓）|

| **大修** | 显式 `--major`（能确认破了契约／流程步骤变了）| 打包 ✓ 分发票 ✓ **必须三线回票** ✓ |

**热修的纪律（别拿"小修"当挡箭牌 ✗）**：
- 热修**也必须**留交接一行 ✓（谁、改了什么、为什么）✗ 不打包 ≠ 不留痕 ✗
- 热修**不许**改判据行为／输出字段／退出码语义——那已经超出小修 ✗ 走中修 ✓
- 攒着的中修超过 **3 天**或**3 处** ⇒ 立刻发一版 ✓ 否则别人手上的包会太旧 ✗

## 12. 四线以上：加"认领"和"票号"

### 12.1 四条措施

| 措施 | 做法 |
|---|---|
| 去歧义 | 票号 `T-日期-线+序号` ✓ |

### 12.2 认领行的格式（v1.2 写死 · 现场踩过）

```
认领：<线>（10:40 UTC+8）          ← ✓ 就这样，纯文本一行
**认领**：<线>（10:40 UTC+8）      ← ✗ 别加粗（机器看不见 ✗）
```

- **不要加粗** ✓ 也不要用列表符号包一层 ✓ —— markdown 修饰会让一行**人对人可见、对机器不可见** ✗
- 检查器已**兼容**加粗（v1.2 ✓）但**规范仍写"别加粗"** ✓ —— 双保险 ✓ 因为别的工具不一定兼容 ✗
- 现场实测：加粗写法让认领统计变成 `2/3` ✗ 实际是 `4/4` ✓ —— 差的那两个就是"看起来写了其实没写" ✗
- 认领行是**事件**（可以多行 ✓ 换人追加不覆盖 ✗）；当前负责人是**字段**（票头 `负责人：` 只有一行 ✓）

**不建议**上锁服务、一票一文件、独立工作副本 ✗ —— 除非试行发现真的并行冲突 ✓。

### 12.3 通知 / 签收 / 检查点（v1.4 补写 · **上一轮说写了，其实没写** ✗）

> 《给 GPT 的复核回执》§3 原文：「（请求号 ＋ 签收 ＋ 检查点）**采纳为可选机制 ✓ 写进 §13**」

| 机制 | 写法 | 效果（诚实版） |
|---|---|---|
| **请求号** | 跨线请求在票里挂 `T-20261025-C03/R01`（一票多请求就 `/R02`）✓ | 便于"只回其中一条"时能点得到位 ✓ **不解决送达** ✗ |

- ✗ 不做轮询守护、不加通知服务（§14 落地清单不变 ✓）

## 13. 常见失效写法 → 正确写法

| 容易误导的写法 ✗ | 更可信的写法 ✓ |
|---|---|
| 应该好了 | 已通过哪些检查；还有哪些未验证 |
| 全部通过 | 本次执行了哪些检查，覆盖什么范围 |
| 已修复，等用户确认 | 实现已交付；若用户验证是必要标准 → 状态 `[v]` |
| 改前很慢，改后快很多 | 有测量给方法样本；无基线写"改前未采集" |
| 已备份 | 备份范围、位置、校验结果、是否演练恢复 |
| 没复现，做不了 | 当前证据不足；可继续哪些调查，需要哪项关键输入 |
| 等对方 | 等谁完成什么，满足什么条件恢复，谁跟进 |
| 有锁文件，绝不会冲突 | 说明实际互斥机制与验证范围；只有约定就写清限制 |
| 写了票对方就会处理 | 已记录；是否通知、谁认领、何时检查分别说明 |
| 旧票有 `[x]` 等于新规则下通过 | 历史已标完成；本次未追溯复核 |

## 附录 B：可移植的票板检查器（参考实现 · 55 行）

> 本仓的 `tools\ticket-check.mjs` 是**绑定我们自己格式**的完整版 ✗
> 下面这份是**给别项目抄的骨架** ✓ 只依赖 node，无第三方包 ✓ 只读 ✓

```js
// ticket-check.mjs —— 票板结构自检（只读 · 零依赖 · 可改）
// 用法：node ticket-check.mjs [路径] [--list]
import { readFileSync } from 'node:fs';

// ── 按你的项目改这 4 组常量 ──────────────────────────────
const FILE = process.argv[2] && !process.argv[2].startsWith('--') ? process.argv[2] : 'docs/待办.md';
const LIST = process.argv.includes('--list');
const HEAD = /^## \[([ ~vx-])\] \[([^\]]{1,40})\](.*)$/;   // 票头：状态位 + 路由 + 标题
const ID = /T-20\d\d\d\d\d\d-[A-Z]\d{2}/;                  // 票号
const ACCEPT = /验收/;                                      // "验收方式"字样
const REPLY = /✅/;                                        // 回票标记
const CITED = /回「|T-20\d\d\d\d\d\d-[A-Z]\d{2}/;            // 回票有没有点名
const SECRET = /(password|passwd|secret|token|api[_-]?key|密码|口令)\s*[=:：]\s*\S{6,}/i;
// ─────────────────────────────────────────────────────

const lines = readFileSync(FILE, 'utf8').split(/\r?\n/);
const tickets = [];
let fence = false;
lines.forEach((l, i) => {
  if (/^```/.test(l.trim())) { fence = !fence; return; }
  if (fence) return;                                  // 跳过代码块里的示例票头
  const m = HEAD.exec(l);
  if (m) tickets.push({ i, state: m[1], route: m[2], title: m[3].trim(), old: false });
  else if (/^## \[[^\]]{1,40}\]/.test(l)) tickets.push({ i, state: '?', route: '?', title: l.slice(3, 60), old: true });
});

const out = [];
const add = (kind, t, why) => out.push({ kind, line: t.i + 1, t, why });

for (const t of tickets) {
  if (t.old) add('格式', t, '票头缺状态位（应为 `## [ ] [路由] 标题`）');
  if (!/20\d\d-\d\d-\d\d/.test(lines[t.i])) add('时间', t, '票头没写日期');
}

const ids = new Map();
for (const t of tickets) {
  const m = ID.exec(lines.slice(t.i, t.i + 3).join(' '));
  if (!m) continue;
  ids.set(m[0], [...(ids.get(m[0]) || []), t]);
}
for (const [id, list] of ids) if (list.length > 1) add('票号重复', list[1], id);

for (let k = 0; k < tickets.length; k++) {
  const t = tickets[k];
  const end = k + 1 < tickets.length ? tickets[k + 1].i : lines.length;
  const block = lines.slice(t.i + 1, end).join('\n');
  if (REPLY.test(block) && !CITED.test(block)) add('回票未点名', t, '有回票但没有「回『原票』」或票号');
  if (t.state === 'x' && !REPLY.test(block)) add('完成缺证据', t, '[x] 但没有回票');
  if (t.state === ' ' && !ACCEPT.test(block)) add('缺验收方式', t, '[ ] 但没有「验收」字样');
  if (t.state !== 'x' && SECRET.test(block)) add('疑似凭据', t, '未结票里有疑似明文凭据');
}

const cnt = {};
for (const t of tickets) cnt[t.state] = (cnt[t.state] || 0) + 1;
console.log(`票 ${tickets.length} 张｜待处理 ${cnt[' '] || 0}｜处理中 ${cnt['~'] || 0}｜待验收 ${cnt.v || 0}｜已完成 ${cnt.x || 0}`);
if (!out.length) console.log('✅ 结构自检通过（≠ 做对了 ✗）');
else {
  const k = {}; for (const p of out) k[p.kind] = (k[p.kind] || 0) + 1;
  console.log('⚠ ' + out.length + ' 条：' + Object.entries(k).map(([a, b]) => a + ' ' + b).join('｜'));
  if (LIST) for (const p of out) console.log(`  L${p.line} [${p.kind}] ${p.t.route} ${p.t.title.slice(0, 40)} — ${p.why}`);
  else console.log('（加 --list 逐条列）');
}
```

### 移植三步

1. **改常量**：`HEAD` 的状态符、`ID` 的票号格式、`ACCEPT` 认的字样（比如你的项目叫「复验方式」）
2. **改路径**：`FILE` 默认值换成你的票文件
3. **降噪**：第一次跑一定一堆历史票问题 ✓ 属正常 ✓ 用 `--list` 看一遍，只盯**新票** ✓

### 一条经验

> 写这工具**最大的收益不是它查出来的问题** ✗，而是写它的时候你会发现：**你自己那些"约定"里，有一半根本没法被机器判** ✓
> 判不了的那一半，就是以后会咬人的那一半 ✓

## 16. 试行观察项（照现场保留意见加的）

> 现场原话：「v1.1 加了五状态和票号，**仪式感比我们实际需要略重**。选择性全采纳，但**只在新票上执行**：老票不动，新票按新规走。如果一周后发现 `[~]` 从没被用过，**再砍它**——这正是 §12 说的'除非试行发现真的并行冲突'。」

### 16.1 只在新票上生效（老票不回填）

- 老票**只改票头格式** ✓ 让判据扫得到 ✓
- **不回填**日期、验收方式、负责人、结论 ✗ —— 那是**补造历史证据** ✗
- 历史 `[x]` 缺证据的 → 标"历史已标完成，未按新规则复核" ✓ 不重开、不升级 ✓

### 16.2 三条"该砍就砍"的判据（连续 10 张新票统计）

| 项 | 观察什么 | 判据（v1.3：**触发复核**，不是"砍"✗） |

### 16.2.1 计数方式（这个坑要单独说）

**认领位 `[~]` 不能用"当前状态"来数** ✗ ——

⇒ 一张真用过认领的票，会被统计成"从没用过" ✗ → 然后被"砍功能" ✗ **这是自指式误判的另一种形态** ✗。

**正确做法**：数票内的 **`认领：<线>（时分）` 那一行** ✓
—— 这也是 §12.2 要求写那一行的**第二个理由**：它既是给人看的抢注痕迹 ✓ 也是给机器数的证据 ✓。

同理，"票号被引用"要**排除 `**票号**：T-…` 这个声明行本身** ✗（否则每张票都算引用了一次 ✓ 指标立刻失效 ✗）。

**v1.3 再收三条（GPT 复核抓到的）**：

2. **分母 = 有回票记录的票** ✓ 不是"所有样本票" ✗（没开始的票凭什么算"没标"✗）
