## 0. 一句话说清它是什么

**把"口头协作"变成三份可检索的文件：谁的地盘、干过什么、有什么事等着谁。**

- 出问题 → 不是去群里喊，而是**开一张票**
- 干完活 → 不是靠记忆，而是**追加一行交接**
- 有疑问 → 不是猜，票里写清**复现步骤 ＋ 验收方式**

**不适用**：一个人、一个会话、一件事 ✗ —— 三份文件是纯开销 ✗

## 1. 三份文件

```
docs/
├─ 角色分工.md    ← 契约：谁改什么、不许动什么、验收授权、收工标准（很少改）
├─ 待办.md        ← 票：状态与验收细节（只追加，票永不删）
└─ 交接.md        ← 顶部：当前状态速查（可更新）｜底部：历史流水（只追加，只写指针）
```

**一项工作的状态只在一个地方维护 → 票里** ✓
交接若转述状态，必须带票号与时间 ✓ 两者不一致时**以票为准** ✗ —— 不是以"哪个文件最后保存"为准 ✗

## 2. 角色与所有权（模板）

| 角色 | 负责 | 可以改 | **绝对不许改** |
|---|---|---|---|
| **代码线**（调试/系统） | 引擎、代码、服务端、工具、部署、排障 | 代码目录、构建脚本、工具 | 内容数据、别人负责的配置 |
| **内容线**（卡/文案/人格） | 内容、文案、数据 | 内容数据文件、自己新建的工具 | 代码目录、既有测试脚本 |
| **发布线**（分发/平台） | 平台配置、上架、费率、账号 | 平台侧配置、发布脚本 | 本地代码与内容 |
| **人类（主人）** | 拍板、给真实素材、裁决体验 | 什么都可以，但**不写实现细节** | —— |

要点：

- **数据与代码分离** ✓ 内容线只碰数据，代码线只碰代码
- 按**文件所有权**划分 ✓ 但写清"同一文件的实际写入仍需协调" ✓（按字段分工 ≠ 文件级隔离 ✗）
- 允许**临时接管**：接管前确认原线已停写、重读最新版、记录接管边界 ✓ **超时不构成自动接管** ✗

## 2.9 传话不是通道（2026-10-27 · 实机问题）

> 主人传话只是**提醒** ✓ 不是"已通知到位" ✗

- 要谁做事 ⇒ **开票**：`node tools/ticket-relay.mjs --from 我 --to 对方 --title "…" --write` ✓
- 谁做完了 ⇒ **回票** ✓ 只在对话里说＝没留痕 ✗
- 纯信息 ⇒ 不开票 ✓ 但回一句「只通知 ✓」

**一句话**：让"传话"和"开票"是**同一个动作** ✓ 否则人一定选省力的那个 ✗

## 3. 票：格式与硬规则

### 3.1 票头：状态位必须在最前

```markdown
## [ ] [卡片→调试] 标题（2026-10-25 10:40 UTC+8）
## [~] [卡片→调试] 标题        ← 处理中（票内加一行「认领：<线>（10:40）」）
## [v] [卡片→调试] 标题        ← 回票了，等对方复验
## [x] [卡片→调试] 标题        ← 已验收通过
## [-] [卡片→调试] 标题        ← 已取消（必须写理由）
```

| 规则 | 为什么 |
|---|---|
| 状态符只有 ` ` `~` `v` `x` `-` 五种，**在第一段方括号里** | 写成 `## [宿主→系统线] 标题` ⇒ `grep '^## \[ \]'` **永远是 0** ✗ 不是"没票"，是"永远扫不到" ✗ |
| 方括号里**只放状态**，路由放第二个方括号 | 一个方括号装两样东西，机械判据就没法剥 ✗ |
| **绝不许从正文关键词猜状态** | 票正文只要出现"结票改 `## [x]`"，判据就**自指** ✗ 没干的票被判成完成 ✗ |
| 时间带**时区**；同一天多次改动带**时分** | 容器 UTC ✗ 服务 UTC+8 ✗ 同一件事差 8 小时 ⇒ 时间线判反 ✗ |

**认领是事件，不是状态**：`认领：D（10:40 UTC+8）` 可以有多行 ✓ 换人**追加不覆盖** ✓
它是"便于发现双认领" ✗ 不是锁 ✗ —— 两人仍可能同时读到 `[ ]` 各自认领，**别宣称"已杜绝"** ✗

### 3.2 票号

格式：`T-<YYYYMMDD>-<线代号><两位序号>`，例 `T-20261025-D03`

- 线代号固定：`D` 调试 / `C` 卡片 / `P` 线上（各项目自定 ✓）
- **序号按线各自递增** ✓ 不要所有线抢"最大号 +1" ✗
- 用途：回票靠票号定位 ✓ 交接只写票号 ✓ 不再复述整张票

**位置与读法（两条要分开看，别互相依赖）**：

| | 约定 |
|---|---|
| 写在哪 | `**票号**：T-…` 一行，紧贴票头第二行 ✓（位置可预期 ✓）|
| 怎么读 | 检查器**先切票块**（票头 → 下一票头之前），票号在**本块内任意位置**都读得到 ✓ **绝不跨到下一张票** ✗ |

- 块内**声明行**有**两个不同**票号 → 报「票号歧义」✗ 一个都没有 → 报「缺票号」✗ **不从正文/下一票补猜** ✗
  > **口径（v1.6 钉死）**：歧义**只看声明行**（`**票号**：T-…`）✗ 正文里写"我开的第一张就是 T-…-D05"不算 ✗
  > 按"块内出现过就算"实现，实测把三张票判成歧义 ✗ 全是误报 ✗（正文互相指路是五线并行的常态 ✓）
- 为什么不能按"前 10 行"读：认领行 ＋ 复现步骤一多，票号就被挤出窗口 ✗ 实测漏一张 ✗

### 3.3 一张新票必填的四组

```markdown
## [ ] [卡片→调试] 标题（2026-10-25 10:40 UTC+8）

**票号**：T-20261025-C03
负责人：调试｜验收方：卡片｜阻塞：无
**现象 / 目标**：<一句>
**验收方式**：<命令 ／ 读字段 ／ 截图 ／ 样本对照，四挑一>
```

- `负责人｜验收方｜阻塞` 只写**当前** ✓ **别再另写一行 `**状态**：`** ✗（两处维护必然漂移）
- ⚠ **写具体责任人** ✗ 不写 `D`／`C`／`F` 代号 ✓（代号只用于票号前缀和路由 ✓）—— 写代号等于把信息藏进表里 ✗
- 按需追加：环境、复现、证据、依赖、数据风险、回滚点、`请求号 T-…/R01`、`签收：<线>（时分）`
- **纯说明性修订**不强制填运行环境／基准测量／多套回滚 ✗

### 3.4 验收方式：**可自证**是第一要求

四种都算数 ✓ 关键不是"必须是命令"✗，而是"**对方能自己核对**" ✓：

| 形式 | 例子 | 适合 |
|---|---|---|
| 命令 | `node tools\run-all-tests.mjs` → 17 组全绿 | 有 shell 的线 |
| 读字段 | 读 `data/x.json` 的 `provider.model` = `deepseek-flash` | 没 shell 的线 ✓ |
| 截图 | 800×1280 与 1500×900 各一张 ＋ 应看到什么 | 布局/界面 |
| 样本对照 | 改前 3 段 vs 改后 3 段 ＋ 明确检查项 | 文风/文案 |

**四条硬约束**：

1. ✗ **不许自指** —— 想证明"文件里没有密码"，写 `grep -c '<密码>' 待办.md` 会把密码写进被检文件 ⇒ 永远命中 1 ✗
   → 换判据：先划清**被检数据范围** ✓ 用**已知阳性/阴性样本**验证判据**有区分能力** ✓ 正则断开匹配串 ✓ 换独立观察点 ✓
   （**别指望**哈希/行号当通用证明 ✗ 哈希只证明"和某个已知版本一致" ✗ 行号会漂 ✗）
2. ✗ **判据要能区分真假** —— 没测基线就写"期望 0"是猜 ✗ → 先跑一次看现状 ✓ 或明写"改前未采集" ✓
3. ✓ **标执行位置与权限**
   ```bash
   # @容器内 · 普通用户
   grep -c '…' /workspace/proj/docs/待办.md
   # @宿主机 · sudo
   sudo -n docker exec <容器> sh -c '…'
   # @无 shell 的线 → 由宿主线代跑（注明代跑者）
   ```
   **并且说清"这是谁的环境"** —— 描述环境时**限定作用域**，三选一：
   `该会话当前`（本次沙箱就是这样）／`该线约定`（长期这么干）／`该机器`（物理/容器事实）
   > 现场踩过：写"人设线没有 shell，跑不了检查器" ✗ —— 那是**那一次会话的沙箱策略** ✗ 不是"线的属性" ✗
4. ✓ **注意退出码** —— `set -e` 下 `grep -c` 命中 0 是**退出 1** ✗ 用 `|| true` 或 `if ! grep -q` ✓

### 3.5 凭据禁区

**票面 / 交接 / 验收命令里出现凭据 = 把凭据写进历史** ✗

- 票与日志是**永久留存物** ✓ 事后只能轮换，**旧值仍躺在历史里** ✗
- 只写指针：`见 data/secrets/x.env` ✓
- Windows 上 `chmod 600` **无效** ✗（NTFS 用 ACL）→ `icacls "<文件>" /inheritance:r /grant:r "<用户>:F"`
- `systemd EnvironmentFile` 是**明文** ✓ 挡"别人读不到" ✗ 挡不住 root ✗

## 4. 回票

### 4.1 模板

```markdown
> ✅ **【2026-10-25 10:52 UTC+8 · 调试：<结论一句>】回「<原票标题关键词>」（T-20261025-C03）**
> 状态：**[v] 待验收**
>
> **改了什么**：1. … 2. …
> **实测（改前 → 改后）**（证据标签：自动测试实测 / 目标环境实测 …）
> | 指标 | 改前 | 改后 |
> |---|---|---|
> **请复跑**：`<方式>`（@位置 · 权限）  期望：<具体预期>
> **已知限制**：<没解决的，别藏>（无则写"无"）
```

> ⚠ **回票只有首行用 `✅`** ✓ 正文字面用 `✓`／"通过"✓ 演示边界符请放代码围栏 ✓（`> ``` ` **引用围栏也算围栏** ✓ v1.10.32 起块内 ✅ 不再被当成回票 ✗）
> 　—— 正文多一个 `✅` 会被当成**新回票** ✗ 正常情况下只多一条统计 ✓ 特定文本下**会改变归位目标** ✗

### 4.2 为什么必须点名

只追加 ＋ 多线交叉 ⇒ **"回票在原票下面"是错的** ✗
实测：A 线开票在第 223 行，回票落到第 246 行另一张票之后 ✗ 扫描器按相邻段落判断 ⇒ 判成未处理 ⇒ 差点去催一件做完的事 ✗

### 4.3 回票 ≠ 完成

- 回票只把状态推到 **`[v]` 待验收** ✓
- 只有**票面约定的验收方**给结论，才改 `[x]` ✓
- 提交修复的人**不因提交自动成为验收人** ✗
- 低风险小改（错字、无共享影响）可在契约里**预先授权自验收** ✓ 并写明"按约定自验收" ✓

### 4.4 证据五档（写在回票记录里）

`静态检查`｜`自动测试实测`｜`目标环境实测`｜`人工样本复核`｜`未验证`

- **单测通过 ≠ 目标环境通过** ✗ 布局/滚动/输入法/端口/权限类问题，**第一次就要真机验** ✓
- 标签只写在**回票记录**里 ✓ 正文写一句"证据标签可选：静态检查／…"是**模板** ✗ 不算标注 ✗

### 4.5 改前基线缺失

写 **"改前未采集"** ✓ 不补造数字 ✗
不写"自然度提高 35%"这种**没有定义的分** ✗
性能类要给场景、样本数、环境是否可比 ✓ 单次数字不能写成"稳定提升" ✗

### 4.6 回票归位：**一对**判据 ＋ 三步搬运（v1.6）

回票落错位置有**两个方向**，必须**成对**做 ✗ 只做一个，人就只修一半 ✗

| | 长什么样 | 谁会发现 |
|---|---|---|
| **A** | 本块**有** `✅`，点的却是**别的票** ⇒ 别人的回票被塞进了这块 | 检查器：「回票指向别的票」|
| **B** | 本块**没有** `✅`，但文件**后面**出现了它的票号/标题 ⇒ 它自己的回票被塞到别处 | 检查器：「回票不在票块内」|

**归位三步**：

1. **先备份**票板 → 放仓库内 `.backups/` ✓ 别放 `/tmp` ✗（§10.4）
2. **按声明票号定位**目标块 ✗ 别用"块内出现过这个号"✗
   **匹配顺序（通则，不只票号）**：① 独占一行的 `**票号**：<id>` ✓ ② 票头行含号 ③ 块内出现过号 —— **最弱，必然误伤** ✗ 只当兜底 ＋ 人工确认
   实测代价：用第 ③ 种，把 C01 的回票插进了 D05 的块 ✗（D05 正文里写着"我开的第一张就是 C01"✗）
3. **整段搬**（`> ✅` 那一整组引用行）✓ 一个字不改 ✗ 搬完**两向都复跑**（A、B 都该消失）✓

> **五线以上的真发现**：最需要被检验的**不是"谁在干活"** ✗ 而是"**谁的证据落在了正确的位置**" ✓
> 四线还能人肉对一下 ✗ 五线之后位置错了没人发现 ✓ 只有 lint 会发现 ✓

**工具（v1.7）：`tools\ticket-reply.mjs`**

```bash
node tools\ticket-reply.mjs                          # 预演：搬哪几行、搬去谁（不写盘 ✗）
node tools\ticket-reply.mjs --write                  # 先快照 → 逐条搬 → 内容守恒 → 复跑 lint
node tools\ticket-reply.mjs --write --close T-…-H02  # 再推 [v] → [x]
```

- **默认不写盘** ✓ 因为它改共享文件 ✗ 每次改写都该先被人看一眼 ✓
- 定位**声明优先** ✓ 猜不准就**不动**并报出来 ✗（宁可留给人，也不制造"看起来归位了"的假象 ✗）
- `--close` 三道闸：只有 `[v]` 能推 ✓｜块里**必须有回票记录** ✗｜只改票头一行 ✓ 多改一行就中止 ✗
- ⚠ 它只保证**结构**（位置对）✓ 不保证回票内容可信 ✗ 验收仍走票面约定的验收方 ✓

> **v1.7 修的一个真漏报**（写这工具时抓到的）：原来 A 向判据还要求"回票里没有「回…」"✗
> 可落错块的回票**几乎都带着「回『标题』」** ✗ ⇒ 那个条件让判据对**最常见的形态直接失明** ✗
> ⇒ 改成**只看票号**：与自己声明的号不符就报 ✓（加用例 13 锁死，防以后又加回去）

### 5.1 只写指针

### 5.2 指针必须能落到票（可机械核对）

- 落点按**票号声明**判 ✗ 不按"文本里出现过"✗（后者会把票板头部模板里的示例号算成"有这张票"✗，实现时真踩到过）
- **行内代码里的票号**（`` `见 T-…` ``）视为示例/模板 ⇒ 只计数、不判定 ✓（真踩到过：规则说明那行被当成指针 ✗）

| 情况 | 做法 |

| 步 | 做法（两人同时改 `待办.md`）| 合格 ✓ | 不合格 ✗ |
|---|---|---|---|
| 1 | 甲、乙各在自己段落**追加** 1 行，都不重排全文 | 两份内容**都在** ✓ | 一方的行**消失** ✗ |
| 2 | 故意制造同段冲突（两边都从同一行往下追加）| **保留双方** ✓ 顺序不理想可以接受 ✓ | 谁"最后保存"谁赢 ✗ |
| 3 | 事后追问"这一行是谁加的、什么时候" | 能**指出来源**（作者 ＋ 时间 ＋ 出处）✓ | 说不清是谁的 ✗ |
| 4 | 来源查不清 | **暂停该文件** ✓ 记一行 ✗ | 继续往上叠 ✗ |

> 别宣称"已杜绝" ✗ 分段追加只是**降低**冲突概率 ✓ 它不互斥 ✗

## 7. 一轮完整流程（10 步）

1. **读上下文**：契约摘要 → 当前速查 → **两个队列** ✓
   · **我要处理的** `[ ]` / `[~]` ✓　· **我要验收的 `[v]`** ✓ ← 只读第一个 ⇒ 回票后的活从双方视野消失 ✗
   别只按状态跳过 ✓ 要按"**现在轮到谁响应**"✓ 不要求读完全部流水 ✓
2. **整理成票**：现象 → 票；低风险同线小改按简化规则 ✓
3. **认领**：`[ ]` → `[~]` ＋ 一行 `认领：<线>（时分）` ✓
4. **复现/取证**：能复现就复现 ✓ 不能则做只读调查并标"未复现" ✓
5. **留恢复点**：按改动性质备份 ✓ 校验备份**能读回** ✓
6. **实施**：只改自己的地盘 ✓ 保护别人未提交的改动 ✓
7. **回票**：改了什么 ＋ 改前→改后 ＋ 已知限制 ＋ 复跑方式 ✓ → `[v]`
8. **验收**：按票面标准判 通过/失败/阻塞 ✓ 通过才 `[x]` ✓
9. **交接**：一行指针 ✓ 更新速查 ✓
10. **收工三件套**（这是"必然发生的检查点"）✓
    · `node tools\ticket-check.mjs --trial`（0.2 秒 ✓ 只读 ✓）
    · **读一眼别人的 `[v]` 和请求号 `T-…/R01`** ✓
    · 写交接行（带票号/数字/时区 ✓）

> 为什么把检查挂在**收工**上：**一条线整天不干新活时，它不经过任何"开工检查点"** ✗
> 但它**总要收工** ✓ ⇒ 检查点分**开工类**（会漏 ✗）＋ **收工类**（必然发生 ✓，不会漏 ✓）
> ⇒ 回票/请求的发现必须挂在收工类上 ✓ 只挂开工类一定漏 ✗

## 8. 判据六条铁律（这一章最值钱）

1. **状态是结构化字段** ✓ 不是正文关键词 ✗（否则自指 ✗）
2. **回票必须点名 ＋ 票号** ✓ 不靠"下面" ✗
3. **验收方式不得自指** ✓ 判据要能区分真假 ✓
4. **证据标五档** ✓ —— **单测通过 ≠ 目标环境通过** ✗
5. **同一问题连续返工三次 ⇒ 强制复盘**：记原假设、反证、尚未观测的信息、下一项调查 ✓
   —— 但**不能用"还没到第三次"延后本来必要的环境验证** ✗
6. **自动化巡检的空 ≠ 空闲** ✓ 输出必须带作用域：`本线 0 张待办（不含其他线）` ✓

### 9.0c 临时项目：用工具造，别手写路径（v1.10.24）

### 9.0d 闭环五问（v1.10.28）

```bash
node tools/ticket-check.mjs --loop
```

① 事事有回应（超 24h 无回票）② 件件有着落（负责人/验收方不是职务）③ 凡事有交代（`[x]` 无点名回票）
④ 句句有回答（票面有疑问却无回票）⑤ 沟通有闭环（`[v]` 超 12h 未关）

只读 ✓ 恒 exit 0 ✓ 阈值：`docs/.ticketrc.json` 的 `loop` 段 ✓
**局限**：回票手写时间常带 `x` ⇒ 超时只看票头时间 ✗ ④ 只判"完全没回"，不判"答全没答全"✗

### 9.1a 口径：`unknown` 怎么读（v1.10.23）

- `unknown` ＝ 无票号且判不了年代 ⇒ **仍算 real** ✓ 但**不是已确认新增** ✗
- **三栏一起报**：`real = knownReal + unknown + unclassified` ✓ 答法「已确认 N；另有 M 判不了」✓
- 门禁要稳 ⇒ `--assume-debt`（只改口径与门禁 ✓ 不改判定 ✗ JSON `assumedDebt` 可查 ✓）

### 9.1b 真问题 vs 历史债（v1.8 · 这是最影响可用性的一条）

**病**：老项目一加「缺票号」判据，问题总数从 12 跳到 24 ✗ 一半是常量 ✗
⇒ "这次有没有新增问题"这个最常问的判断，只能靠人眼减 ✗ 数字从此失去信号 ✗

**双特征**（两条同时成立才算历史债）：

1. 本票块内**没有** `**票号**：` 声明
2. 票头时间**早于**票号制度生效日（`--debt-since`，默认 `2026-10-25`）

- 任一不成立 ⇒ **真问题** ✓
- 票头**没日期** ⇒ 判不了 ⇒ **fail-closed 算真问题** ✓ 并单独标「无法判定」✗（别读成"今天新增"✗）
- `--list` 只列真问题 ✓ `--list --all` 连历史债一起列 ✓ 历史债**不修** ✗

### 9.2 它**不能**做什么（别当质量门）

- ✗ 证明代码正确、截图真实、用户满意
- ✗ 判断"验收方式能不能真的区分真假"（自指、阈值拍脑袋它看不出来）
- ✗ 代替人工复核 —— 它只是 **lint**（结构检查）✓ 不是通过条件 ✗

**别挂 CI** ✗ —— 历史票本来不合规 ✗ 会一直红 ✗（v1.8 起至少能靠"真问题 0"当门 ✓ 但那是另一件事 ✓）

### 9.3 怎么用

- 每张新票**写完立刻跑** ✓ 比事后补格式便宜 ✓
- 收工前顺手跑一次 ✓ 只看「本次新增的票」那几条 ✓
- 交接里写了 `T-…` 就 `--with-handoff` ✓ 报了悬空 ⇒ 票号抄错 ✗ 或票没开 ✗
- 归档前跑一次 ✓ 确认要归档的票都已 `[v]`/`[x]` ✓
- **下游要写视图** ⇒ 用 `--json` ✓ 别 import 内部函数 ✗ 也别复制判据 ✗（升级会分叉 ✗）

## 10. 归档（文档增长）

### 10.1 触发条件：**两个都要满足**

- 主文件 **> 400 行** ✓ **且** 已完成票（`[x]`/`[-]`）**≥ 10 张** ✓
- 只满足一半 ⇒ **不搬** ✗ 在交接写一行"无票可归档（只剩 `[ ]`/`[v]`）"✓
- **别写"结票时顺手"** ✗（会漏）**别写"每周固定"** ✗（靠人记得）—— 绑到可观测动作 ✓

> 实测：归档完 29 张完成票，主文件仍 **689 行**（剩 22 张未结票 ✗ 一张都不能搬 ✗）
> ⇒ 只按行数触发，人就会去搬未结票 ✗ `[v]` 搬走＝让它从双方视野消失 ✗

### 10.2 三步，每步都有校验（不通过就回滚 ✗）

| 步 | 做什么 | 校验 |
|---|---|---|
| 1 | **先备份** `docs/待办-备份-<YYYYMMDD-HHMM>.md` | 备份**能读回**：`wc -l` 与原文件一致 ✓ |
| 2 | **按票块整块搬**（票头 → 下一票头之前）✗ 不按行号 ✗ 不改一个字 ✗ | 主文件**少 N 行** ＝ 归档**多 N 行** ✓ 两文件拼起来**逐字等于备份** ✓ |

### 16.1 先记住两条计数坑

## 附录 A：可移植的票板检查器（55 行骨架 · 给别项目抄）

> 本仓 `tools\ticket-check.mjs` 是绑死自己格式的完整版 ✗ 下面是**零依赖、只读**的骨架 ✓

```js
// ticket-check.mjs —— 票板结构自检（只读 · 零依赖）
import { readFileSync } from 'node:fs';
const FILE = process.argv[2] && !process.argv[2].startsWith('--') ? process.argv[2] : 'docs/待办.md';
const LIST = process.argv.includes('--list');
const HEAD = /^## \[([ ~vx-])\] \[([^\]]{1,40})\](.*)$/;
const ID = /T-20\d\d\d\d\d\d-[A-Z]\d{2}/;
const ACCEPT = /验收/;
const REPLY = /✅/;
const CITED = /回「|T-20\d\d\d\d\d\d-[A-Z]\d{2}/;
const SECRET = /(password|passwd|secret|token|api[_-]?key|密码|口令)\s*[=:：]\s*\S{6,}/i;

const lines = readFileSync(FILE, 'utf8').split(/\r?\n/);
const tickets = [];
let fence = false;
lines.forEach((l, i) => {
  if (/^```/.test(l.trim())) { fence = !fence; return; }
  if (fence) return;                                   // 代码块里的示例不算
  const m = HEAD.exec(l);
  if (m) tickets.push({ i, state: m[1], route: m[2], title: m[3].trim() });
  else if (/^## \[[^\]]{1,40}\]/.test(l)) tickets.push({ i, state: '?', route: '?', title: l.slice(3, 60) });
});

const out = [];
const add = (kind, t, why) => out.push({ kind, line: t.i + 1, t, why });
for (const t of tickets) {
  if (t.state === '?') add('格式', t, '票头缺状态位');
  if (!/20\d\d-\d\d-\d\d/.test(lines[t.i])) add('时间', t, '票头没写日期');
}
for (let k = 0; k < tickets.length; k++) {
  const t = tickets[k];
  const end = k + 1 < tickets.length ? tickets[k + 1].i : lines.length;
  const block = lines.slice(t.i + 1, end).join('\n');
  if (REPLY.test(block) && !CITED.test(block)) add('回票未点名', t, '有回票但没点名/票号');
  if (t.state === 'x' && !REPLY.test(block)) add('完成缺证据', t, '[x] 但没有回票');
  if (t.state === ' ' && !ACCEPT.test(block)) add('缺验收方式', t, '没有「验收」字样');
  if (t.state !== 'x' && SECRET.test(block)) add('疑似凭据', t, '未结票里有疑似明文凭据');
}
const cnt = {};
for (const t of tickets) cnt[t.state] = (cnt[t.state] || 0) + 1;
console.log(`票 ${tickets.length} 张｜待处理 ${cnt[' '] || 0}｜处理中 ${cnt['~'] || 0}｜待验收 ${cnt.v || 0}｜已完成 ${cnt.x || 0}`);
if (!out.length) console.log('✅ 结构自检通过（≠ 做对了 ✗）');
else {
  const k = {}; for (const p of out) k[p.kind] = (k[p.kind] || 0) + 1;
  console.log('⚠ ' + out.length + ' 条：' + Object.entries(k).map(([a, b]) => a + ' ' + b).join('｜'));
  if (LIST) for (const p of out) console.log(`  L${p.line} [${p.kind}] ${p.t.route} ${p.t.title.slice(0, 40)} — ${p.why}`);
}
```

**移植三步**：① 改常量（状态符、票号格式、"验收"认的字样）② 改路径 ③ 降噪（第一次跑一定一堆历史票问题 ✓ 属正常 ✓ 只盯新票 ✓）
